# Decisions

| # | Phase | Decision | Choice | Reason |
|---|---|---|---|---|
| D1 | Setup | Project layout | Notebooks for EDA; `src/` .py scripts for final pipeline; shared `features.py` | Reviewer can rerun with one command; same cleaning in train and predict |
| D2 | Setup | Environment | venv, Python 3.11.9, Windows 11 | Built-in, lightweight; only pip needed by reviewer |
| D3 | Setup | File names | Renamed to README names in `data/` (underscores) | Spotter's documented score.py command works as written |
| D4 | Setup | Data in repo | Inputs, PDF and Spotter README git-ignored; outputs committed | Data belongs to Spotter; reviewers already have it; originals backed up locally |
| D5 | Setup | Requirements | Spotter's ranges kept; `scikit-learn==1.9.1` pinned exactly | The library that produces predictions must match exactly for reproducible results |
| D6 | Setup | Random seed | `SEED = 42` in `config.py`, passed as `random_state` everywhere (+ `np.random.seed`) | Identical results every run; later rerun with 2–3 seeds to show stability |
| D7 | Setup | Filled December file location | Read blank `data/december_chart_inputs.csv`; write filled copy to `outputs/december_chart_inputs.csv`; score.py run with that path (documented in README) | Never overwrite inputs; deliverable committed in outputs/ (data/*.csv is git-ignored); score.py accepts the path as an argument |
| D8 | Setup | Spotter README | Renamed to SPOTTER_README.md and git-ignored; own README.md committed | Windows file names ignore capital letters, so readme.md and README.md can't share a folder |
| D9 | Setup | Notebook tooling | requirements-dev.txt = `-r requirements.txt` + ipykernel; requirements.txt kept to what reproduces predictions | Reviewer installs only what predictions need; one command installs everything to rerun the notebooks |
| D10 | EDA | Negative weights | Flip sign (absolute value) | 292 train / 145 valid; flipped values match positives in range (5,000–47,500), percentiles and per-equipment medians; spread proportionally across equipment → sign errors |
| D11 | EDA | Missing weight | Fill with one overall training median; no flag | 300 / 165 rows; medians nearly identical across equipment; missing rows priced like others (median factor 1.001 vs 1.000) → random |
| D12 | EDA | Missing market_index | Same-date mean from the same file; fallback previous date's mean, then next date's (safety nets, never triggered); no flag | Varies per load but within ±0.03 inside a date; no fully-missing dates; missingness random (factor 0.994 vs 1.000) |
| D13 | EDA | Extreme rates | Exclude rows with factor <0.5 or >2 vs median rpm by equipment × distance band (edges [0, 250, 500, 1000, 2000, 4000] mi, right-inclusive) from TRAINING only; table learned per training fold; score holdouts on all rows; test vs keeping in Phase 3/4 | Full-file rule flags 677 rows (1.41%; 337 low / 340 high) priced 2–6× off similar loads; uniform across months, equipment, distance; clear gap from normal (98% within ±15%) → consistent with label errors, not spikes. Per-fold counts will differ slightly |
| D14 | EDA | Categories | No clean-up rule; safety check rejects unknown equipment | 3 equipment values, no case/space variants; December text exact |
| D15 | EDA | Distance, coordinates, cities | Keep distance unchanged; use coordinates (relative positions), not city names; December coordinates from training lookup | 70-mile floor + short trips explain high ratios; prices consistent; coordinates synthetic but consistent; 8 cities only in validation (1,447 rows, 12.1%); Laredo outside training map (195 rows) |
| D16 | EDA | quote_signal | Drop; confirm with Jan–Jul → Aug test in Phase 4; no month/date-counter features | ≈ rpm in 5 months, mirrored in 4, noise in Aug; validation spread (0.22) matches Aug (0.223) → unstable, leakage-like |
| D17 | EDA | market_index for December | Validation's daily mean for each December date | December file lacks the column; validation has real values for those dates; a feature, not a label → no leakage |
| D18 | EDA | Cleaning function design | fit_cleaning(train) → saved dict (weight median, city coordinates); clean(df, learned) applies rules to a copy of any file | Learned values come from training rows only (no leakage); one shared function guarantees identical cleaning in train and predict |
| D19 | EDA | Notebook outputs in Git | Committed with outputs | Reviewers see the EDA evidence without rerunning; only small excerpts, not the data files (D4) |
